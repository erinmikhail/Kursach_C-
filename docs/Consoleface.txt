Подсистема взаимодействия с пользователем (ConsoleInterface)
1. Назначение модуля
Модуль ConsoleInterface (пространство имен api) представляет собой внешний слой (API) системы управления базами данных. Его главная задача — обеспечение текстового интерфейса для взаимодействия пользователя или сторонних скриптов с ядром СУБД. Модуль отвечает за считывание SQL-команд, обработку системных мета-команд и форматирование возвращаемых результатов запросов (выборок).

Согласно требованиям технического задания, модуль поддерживает два режима работы, переключаемых через аргументы командной строки:

Интерактивный режим: REPL (Read-Eval-Print Loop), обеспечивающий построчный ввод команд через терминал с немедленным выводом результата.

Пакетный режим: Исполнение последовательности команд, предварительно записанных в текстовый файл (скрипт).

2. Архитектура и основные классы
Модуль состоит из трех основных компонентов:

REPL — класс главного цикла обработки запросов.

JsonFormatter — утилита для сериализации результатов в формат JSON.

TableFormatter — утилита для псевдографического вывода таблиц (используется для отладки).

2.1. Класс REPL (Главный цикл)
Класс инкапсулирует логику получения сырых строковых данных.

Интерактивный режим (start): В бесконечном цикле программа выводит приглашение dbms >  и ожидает ввода пользователя с помощью функции std::getline(std::cin, input). Выход из цикла осуществляется при получении EOF (например, Ctrl+D) или вызове команды выхода.

Пакетный режим (run_batch): Принимает путь к файлу, открывает его с использованием файлового потока std::ifstream. Чтение происходит построчно. Для корректной работы со скриптами, созданными в различных ОС, предусмотрена очистка символа возврата каретки \r на конце строки. Приглашение ко вводу в этом режиме не выводится.

Обработка мета-команд:
Все команды, начинающиеся с символа . (точка), перехватываются до передачи в синтаксический анализатор (парсер). Метод execute_meta_command распознает системные запросы:

.exit — штатное завершение работы приложения.

.clear — очистка терминала с использованием ANSI escape-кодов (\033[2J\033[1;1H).

.help — вывод справочной информации.

2.2. Класс JsonFormatter (Вывод по ТЗ)
Согласно техническому заданию, результатом успешного запроса выборки (SELECT) в терминал должен быть массив объектов в формате JSON. Класс JsonFormatter предоставляет статический метод print для генерации JSON-строки из двумерного массива данных.

Алгоритм работы:

Генерируется открывающая скобка [ для массива объектов.

Осуществляется проход по строкам (rows). Для каждой строки создается JSON-объект {.

Вложенный цикл проходит по столбцам, сопоставляя заголовок (headers[c]) со значением (rows[r][c]).

Эвристика типов данных: Для соблюдения стандарта JSON применяется вспомогательная функция is_numeric. Она посимвольно проверяет строку на наличие только цифр, знака минус и одной десятичной точки.

Если значение числовое (например, id), оно выводится без кавычек.

Если значение строковое (например, name), оно экранируется двойными кавычками.

Алгоритм корректно расставляет запятые между элементами массива и свойствами объекта, избегая лишней запятой после последнего элемента.

2.3. Класс TableFormatter (Вывод для отладки)
Форматирует двумерный массив строк в ASCII-таблицу.
Для предотвращения аллокаций памяти под новые массивы строк, алгоритм работает напрямую с исходными данными:

Сначала вычисляется максимальная ширина для каждой колонки (widths). Для этого итерируются заголовки и все строки данных. Для предотвращения разрыва верстки терминала применяется константа ограничения ширины ячейки kMaxCellWidth = 50.

Отрисовка производится построчно с использованием манипуляторов потока из <iomanip>. Функция std::setw() задает ширину вывода, а std::left выравнивает текст по левому краю. Избыточно длинные строки обрезаются через std::string_view::substr (Zero-copy операция).

3. Интеграция с точкой входа (main.cpp)
Выбор режима работы осуществляется на этапе запуска приложения путем анализа аргументов командной строки (argc и argv).

Если argc == 1, запускается метод repl.start().

Если argc == 2, первый переданный аргумент (argv[1]) трактуется как путь к SQL-скрипту, и вызывается метод repl.run_batch(argv[1]).
