Lexer (Лексический анализатор)

Назначение:
Lexer выполняет лексический анализ входной строки SQL-подобного запроса —
разбивает её на последовательность токенов (лексем). Каждый токен представляет
собой минимальную смысловую единицу языка, которую в дальнейшем обрабатывает
парсер. Лексер отбрасывает незначащие пробельные символы и выявляет
синтаксические ошибки на раннем этапе.

Основные структуры:
- TokenType — перечисление типов токенов: KEYWORD, IDENTIFIER, NUMBER, STRING,
  SYMBOL, INVALID, END_OF_FILE.
- Token — структура, содержащая тип токена (type) и его текстовое значение
  (value).
- input_ (std::string) — исходная строка запроса, переданная в конструктор.
- pos_ (size_t) — текущая позиция чтения в строке. Последовательно сдвигается
  вперёд по мере разбора.

Логика работы:

1. Инициализация
Конструктор принимает строку запроса и сохраняет её в input_, устанавливая
pos_ = 0. Никакой предобработки не производится.

2. Вспомогательные методы
- peek() — возвращает текущий символ без продвижения позиции. Если достигнут
  конец строки — возвращает нуль-символ '\0'.
- advance() — возвращает текущий символ и сдвигает pos_ на единицу вперёд. За
  пределами строки возвращает '\0'.
- skip_whitespace() — пропускает все пробельные символы (пробел, табуляция,
  перевод строки) с использованием std::isspace. Вызывается перед разбором
  каждого нового токена.

3. Токенизация (tokenize)
Основной метод, реализующий конечный автомат посимвольного разбора. Работает в
цикле while до исчерпания входной строки. Предварительно выделяет память под
вектор токенов с запасом (reserve(input_.size() / 5)) для оптимизации.

Правила разбора:
- Цифра 0-9 или знак '-' перед цифрой -> читается целая и опциональная дробная
  часть (через точку). Поддерживаются отрицательные и вещественные числа.
  Создаётся токен NUMBER.
- Одинарная кавычка ' -> читается содержимое до закрывающей кавычки. Если
  кавычка не найдена — исключение std::runtime_error с указанием позиции.
  Создаётся токен STRING.
- Буква a-z, A-Z или '_' -> читается слово [a-zA-Z0-9_]+. Приводится к нижнему
  регистру и сверяется со словарём ключевых слов: insert, select, from, where,
  update, delete, create, table. При совпадении — KEYWORD (сохраняется в нижнем
  регистре), иначе — IDENTIFIER (сохраняется оригинальный регистр).
- Спецсимволы * , ; ( ) = < > -> создаётся односимвольный токен SYMBOL.
- Пробельные символы -> пропускаются.
- Любой другой символ -> исключение std::runtime_error с указанием символа и
  позиции.

После исчерпания входной строки в конец последовательности добавляется токен
END_OF_FILE.

Взаимодействие с другими модулями:
- Parser — следующий этап обработки запроса. Получает от Lexer вектор токенов и
  выполняет синтаксический анализ согласно грамматике языка.
- Core / Executor — в будущем будет использовать разобранный запрос для
  выполнения операций над базой данных.

Особенности реализации, важные для защиты:
- Поддержка отрицательных и вещественных чисел. Реализована проверка знака '-'
  и дробной точки, что расширяет возможности парсера при обработке значений.
- Move-семантика для строк. Значения токенов STRING, KEYWORD и IDENTIFIER
  перемещаются в Token через std::move, исключая лишнее копирование.
- Резервирование памяти. Вызов reserve() перед циклом токенизации снижает
  количество переаллокаций вектора при разборе длинных запросов.
- Информативные сообщения об ошибках. Исключения содержат позицию проблемного
  символа в исходной строке, что упрощает отладку запросов.
- Расширяемый словарь ключевых слов. Статический unordered_set позволяет легко
  добавить новые ключевые слова без изменения логики токенизации.
- Регистронезависимость ключевых слов. Приведение к нижнему регистру
  обеспечивает корректную обработку запросов независимо от стиля написания
  (INSERT, Insert, insert).
