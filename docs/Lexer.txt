Lexer (Лексический анализатор)

Назначение:
Lexer выполняет лексический анализ входной строки SQL-подобного запроса — разбивает её на последовательность токенов (лексем). Каждый токен представляет собой минимальную смысловую единицу языка, которую в дальнейшем обрабатывает парсер. Лексер отбрасывает незначащие пробельные символы и выявляет синтаксические ошибки на раннем этапе.

Основные структуры:
TokenType — перечисление типов токенов: KEYWORD, IDENTIFIER, NUMBER, STRING, SYMBOL, OPERATOR, TIMESTAMP, INVALID, END_OF_FILE.
Token — структура, содержащая тип токена (type) и его текстовое значение (value).
input_ (std::string) — исходная строка запроса, переданная в конструктор.
pos_ (size_t) — текущая позиция чтения в строке. Последовательно сдвигается вперёд по мере разбора.

Логика работы:
Инициализация
Конструктор принимает строку запроса и сохраняет её в input_, устанавливая pos_ = 0. Никакой предобработки не производится.

Вспомогательные методы
peek() — возвращает текущий символ без продвижения позиции. Если достигнут конец строки — возвращает нуль-символ '\0'.
advance() — возвращает текущий символ и сдвигает pos_ на единицу вперёд. За пределами строки возвращает '\0'.
skip_whitespace() — пропускает все пробельные символы (пробел, табуляция, перевод строки) с использованием std::isspace. Вызывается перед разбором каждого нового токена.

Токенизация (tokenize)
Основной метод, реализующий конечный автомат посимвольного разбора. Работает в цикле while до исчерпания входной строки. Предварительно выделяет память под вектор токенов с запасом (reserve(input_.size() / 5)) для оптимизации.

Правила разбора:
Цифра 0-9 -> читается целая и опциональная дробная часть (через точку). Если в процессе чтения встречаются символы-разделители даты/времени ('-' или ':'), токен распознаётся как временная метка и создаётся токен TIMESTAMP. Для надёжного определения выполняется забегание вперёд с проверкой комбинации разделителей. Если разделители отсутствуют — создаётся токен NUMBER.
Двойная кавычка " -> читается содержимое до закрывающей кавычки. Если кавычка не найдена — исключение std::runtime_error с указанием позиции. Создаётся токен STRING.
Буква a-z, A-Z или '' -> читается слово [a-zA-Z0-9.]+. Полученное слово приводится к нижнему регистру и сверяется со словарём ключевых слов: insert, select, from, where, update, delete, create, table, int, string, not_null, indexed, default, between, and, or, like, sum, count, avg, database, use, revert. При совпадении — KEYWORD (сохраняется в нижнем регистре), иначе — IDENTIFIER (сохраняется оригинальный регистр). Точка разрешена внутри идентификатора для поддержки составных имён вида database_name.table_name.
Спецсимволы * , ; ( ) = < > ! -> обрабатываются с упреждающим чтением (lookahead):
Если текущий символ =, <, > или ! и следующий символ =, оба символа объединяются в составной оператор (==, !=, <=, >=) и создаётся токен OPERATOR.
Одиночные символы =, <, > также создают токен OPERATOR.
Остальные спецсимволы (* , ; ( )) создают токен SYMBOL.
Пробельные символы -> пропускаются.
Любой другой символ -> исключение std::runtime_error с указанием символа и позиции.
После исчерпания входной строки в конец последовательности добавляется токен END_OF_FILE.
Взаимодействие с другими модулями:

Parser — следующий этап обработки запроса. Получает от Lexer вектор токенов и выполняет синтаксический анализ согласно грамматике языка.

Core / Executor — в будущем будет использовать разобранный запрос для выполнения операций над базой данных.
