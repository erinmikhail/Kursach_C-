Задание для Даши Полетаевой мелкое. 
Нужно добить лексер до СЗоП (списка задач от препода).

1. Строковые литералы: По СЗоП строки должны заключаться строго в двойные кавычки ("), а не в одинарные. 
    Замени символ проверки в коде.

2. Составные операторы: В SQL есть операции сравнения: ==, !=, <=, >=. 
    Сейчас лексер читает их по одному символу. Добавь логику lookahead: если видишь =, <, > или !, загляни вперед через peek(). 
    Если там =, считывай их вместе и создавай новый токен TokenType::OPERATOR.

3. Глобальное пополнение словаря (Keywords): 
    Добавь в твой unordered_set новые ключевые слова: int, string, not_null, indexed, default, between, and, or, like, sum, count, avg, database, use, revert.

4. Идентификаторы с точкой: 
    По СЗоП  обращение к таблицам возможно в формате database_name.table_name. 
    Сейчас точка ломает идентификатор. 
    Разреши символу . (точка) находиться внутри слова при считывании идентификатора.

5. Токен Времени (Timestamp): 
    Для команды REVERT нам нужно считывать время в формате yyyy.mm.dd-hh:mm:ss.msmsms. 
    Добавь новый тип TokenType::TIMESTAMP. 
    Напиши логику: если при чтении числа попадаются тире и двоеточия, это нужно собирать в единый токен времени.

Задание для Даши Ротовой:
1. Управление метаданными и схемами (DDL): необходимо реализовать распознавание структуры системы и таблиц.
    Базы данных:CREATE DATABASE [database_name]; — создание новой БД.  DROP DATABASE [database_name]; — удаление существующей БД.  USE [database_name]; — выбор активного контекста.  
    Таблицы:CREATE TABLE [table_name] (col_name col_type [modifiers], ...);.  
    Модификаторы столбцов:NOT_NULL — запрет на пустые значения.  
    INDEXED — создание уникального индекса (B+*-tree ).  
    DEFAULT [value] — значение по умолчанию, если столбец пропущен при вставке.  
    DROP TABLE [table_name]; — удаление таблицы.  
2. Манипулирование данными (DML)Парсер должен корректно извлекать данные для операций над записями.INSERT: 
    Поддержка синтаксиса INSERT INTO [table_name] (col_1, ...) VALUE (val_1, ...);. 
    Необходимо предусмотреть обработку ситуаций, когда список столбцов указан частично.  
    UPDATE: Распознавание команды UPDATE [table_name] SET col_1 = val_1, ... WHERE condition;.  
    DELETE: Парсинг DELETE FROM [table_name] WHERE condition;.  
    SELECT:Выборка всех полей (*) или конкретного списка столбцов.  
    Поддержка алиасов через ключевое слово AS.  
    Агрегатные функции: SUM, COUNT, AVG.  
3. Обработка условий (Блок WHERE) - Это самая сложная часть задания. 
    нужно спроектировать парсер выражений, который будет строить дерево условий для фильтрации данных.  
    Операторы сравнения: ==, !=, <, >, <=, >=.  Диапазоны: val_1 BETWEEN val_2 AND val_3 (интервал [val_2, val_3)).  
    Регулярные выражения: val_1 LIKE val_2 для строковых полей.  
    Сложная логика: Объединение предикатов через AND, OR и группировка условий с помощью круглых скобок ( ... ) для соблюдения приоритета операций.  
4. Дополнительные команды и валидация REVERT: 
    Команда темпорального отката REVERT [table_name] [timestamp];.  
    Валидация:Парсер должен проводить как синтаксическую (корректность SQL), так и семантическую (существование таблиц/колонок, соответствие типов) проверку.  
    В случае ошибки необходимо возвращать информативное описание проблемы пользователю.  

Задача для Ильи: 
Твоя задача — реализовать систему логирования активности, как того требует СЗоП.
Нам нужно записывать в отдельный файл каждое действие пользователя, чтобы можно было провести аудит.  

Что нужно сделать:
Создать класс Logger (api), который будет фиксировать каждый запрос.

1. Формат записи в файле:
Каждая строка лога должна содержать:
Временную метку (Timestamp).
Текст самого запроса (тело запроса).
Статус выполнения (успешно/ошибка).
Время, затраченное на выполнение (в миллисекундах/микросекундах).
2. Технические детали:
Лог должен записываться в файл (например, access.log) в режиме Append (дозаписи), чтобы старые логи не стирались.
Нужно реализовать механизм «авто-сброса» (flush), чтобы даже при аварийном завершении программы последние записи сохранились.
В классе REPL нужно добавить вызов логгера сразу после того, как запрос был «обработан».
3. Пример того, как это должно выглядеть в файле:
Plaintext
[2026-05-07 14:20:01] | REQ: "INSERT 1 'Apple';" | STATUS: SUCCESS | TIME: 1.2ms
[2026-05-07 14:20:15] | REQ: "SELECT * FROM users;" | STATUS: SUCCESS | TIME: 0.8ms
[2026-05-07 14:21:03] | REQ: "INVALID COMMAND" | STATUS: ERROR (ParserError) | T
