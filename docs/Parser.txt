Parser (Синтаксический анализатор)

Назначение:
Parser преобразует последовательность токенов, полученную от лексера (Lexer),
в структуру Statement — промежуточное представление SQL-запроса, пригодное
для исполнения ядром СУБД. Основная цель класса — проверить корректность
порядка токенов согласно упрощённой грамматике команд INSERT и SELECT,
а в случае обнаружения синтаксической ошибки — предоставить информативное
описание проблемы. Код устойчив к выходу за пределы массива токенов.

Основные структуры:
- StatementType — перечисление возможных типов операторов: INSERT, SELECT, UNKNOWN.
- Statement — базовая структура, представляющая распознанную команду. Содержит:
  - type (StatementType) — тип операции,
  - insert_id (uint32_t) — числовой идентификатор для INSERT,
  - insert_text (std::string) — строковое значение для INSERT,
  - select_all (bool) — флаг "SELECT *" (true означает SELECT * FROM table),
  - tokens_ — ссылка на внешний массив токенов (const std::vector<Token>&), без копирования данных,
  - pos_ — текущая позиция в массиве токенов.

Логика работы:

Парсер получает ссылку на уже готовый массив токенов от Lexer и начинает последовательный разбор с начала. 
Важно, что никакого копирования токенов не происходит — Parser работает только с существующими данными.

В методе parse() сначала проверяется, не пуст ли входной поток. 
Если токенов нет, выбрасывается исключение "Пустой запрос". 
Далее берётся первый токен через peek() и проверяется, что он является KEYWORD. 
Если это не так, запрос считается некорректным.

После этого выполняется определение типа команды. 
Так как Lexer уже нормализует регистр, сравнение выполняется напрямую со строками "insert" и "select" без дополнительного преобразования. 
В зависимости от команды вызывается parse_insert() или parse_select().

После завершения разбора основной команды проверяется, есть ли завершающий символ ";". 
Если он присутствует, он поглощается. Если же после команды остаются лишние токены, это считается синтаксической ошибкой.

3. Разбор INSERT — метод parse_insert()
Ожидается строгая последовательность токенов: INSERT → NUMBER → STRING.

Сначала consume() пропускает токен INSERT. Далее обязательно должен идти токен NUMBER. 
Если токена нет или тип не совпадает, выбрасывается ошибка. 
Значение числа преобразуется через std::stoul с проверкой диапазона uint32_t. 
Если число выходит за пределы или имеет неправильный формат, генерируется соответствующее исключение.

После этого ожидается токен STRING. Если его нет или тип неверный — выбрасывается ошибка "ожидалась строка".

В случае успеха формируется Statement с заполненными полями insert_id и insert_text.

4. Разбор SELECT — метод parse_select()
Ожидается последовательность: SELECT → * → FROM → IDENTIFIER.

После consume() проверяется символ "*". 
Далее ожидается FROM, который в текущей реализации приходит как IDENTIFIER, 
поэтому сравнение выполняется по значению строки "from". 
После этого ожидается имя таблицы, которое должно быть IDENTIFIER.

В итоге формируется Statement с type = SELECT и флагом select_all = true. 
Имя таблицы в текущей версии не сохраняется, так как структура рассчитана на дальнейшее расширение.

Работа с токенами реализована через три метода: consume(), peek() и is_at_end(). 
consume() возвращает текущий токен и сдвигает позицию, 
peek() позволяет посмотреть токен без изменения позиции, 
а is_at_end() проверяет выход за границы массива или END_OF_FILE. 
Все обращения к токенам защищены проверками, что исключает выход за пределы массива.

Обработка ошибок построена строго: любое нарушение синтаксиса сразу приводит к std::invalid_argument. 
Сообщения содержат конкретику по ожидаемому и полученному токену, что упрощает отладку. 
Дополнительно обрабатываются ошибки преобразования чисел и проверяется переполнение uint32_t при INSERT.

Взаимодействие с другими модулями:
Lexer поставляет уже готовые токены и не участвует в дальнейшей обработке. 
Parser не работает с исходной строкой запроса, только с результатом лексического анализа. 
Ядро СУБД получает готовый Statement и выполняет операцию. 
В случае ошибок верхний уровень (REPL/CLI) перехватывает исключения и выводит сообщение пользователю без аварийного завершения программы.

Особенности реализации:
Парсер не копирует входные токены и работает через const ссылку, что исключает лишние затраты памяти. 
Методы consume() и peek() возвращают const Token&, что предотвращает копирование строк внутри токена. 
Логика строго линейная — один проход по массиву токенов. 
Поддерживается только минимальная грамматика INSERT и SELECT, любые отклонения считаются ошибкой.
Код устойчив к выходу за границы массива и полностью исключает обращение к несуществующим токенам. 
Parser выполняет только синтаксический анализ и формирование структуры Statement, 
что упрощает дальнейшее расширение системы (WHERE, JOIN, UPDATE и т.д.).
